# Curvature-Aware Path Sensitivity

**Geodesic flow and Jacobi-field testbed** — how a small error in how a path is
started grows into a deviation further along a curved surface, and exactly how
far that prediction can be trusted.

Two stages. The first is calibration: three surfaces where the answer is known
in closed form, so every number can be checked against it. The second takes the
same two objects onto arbitrary parametric surfaces, where there is no closed
form and the verification has to come from somewhere else.

**156 declared checks across both stages, 0 failed.**

## Stage one — calibration on constant curvature

![Geodesic flow and Jacobi fields on the three constant-curvature surfaces](figures/jacobi-testbed-v1.png)

A Jacobi field is the first-order separation between a nominal geodesic and a
neighbouring one. On a surface of constant curvature `K` its transverse
component satisfies

```text
j''(s) + K j(s) = 0,    j(0) = 0,    j'(0) = 1
```

with solutions `s`, `sin s` and `sinh s` for `K = 0, +1, -1`. This repository
integrates the geodesic flow and that equation numerically, checks both against
those closed forms, and — the part that actually matters — measures where the
first-order answer stops being an answer.

Everything below is regenerated by one command and recorded, with a pass/fail
threshold on every claim, in [`validation/report-v1.json`](validation/report-v1.json).

**109 declared checks, 0 failed.**

| what was measured | result |
|---|---|
| order of accuracy, Euler / midpoint / RK4 | 1.02 / 1.96 / 3.93 on the sphere, 0.97 / 1.98 / 3.97 on the hyperbolic plane |
| flat model | every method exact to `< 1e-13`; no order exists to measure, and the report says so |
| RK4 drift off the unit tangent bundle | `4e-14` (sphere), `2e-13` (hyperbolic), with no re-projection applied |
| separation of two geodesics | `sn_K(d/2) = sn_K(s)·sin(ε/2)` — one law of cosines for all three curvatures |
| error of the first-order prediction | grows as `ε²` with coefficient `cn_K(s)²/24`, matched to 3e-5 … 1e-4 relative |
| first-order validity at `s = 1`, to 1e-6 | `ε ≤ 0.52°` (sphere), `0.28°` (plane), `0.18°` (saddle) |
| conjugate point on the sphere | found at `s = 3.141592653589791`, error `2.2e-15` |
| loss of minimality past it | excess length matches `2(s - π)` to `7.1e-15` |

Two failure modes are measured rather than assumed. The **model** fails from
above, as `ε²`. The **numerics** fail from below — but only when the two
geodesics are flowed at different resolutions; advance the whole fan with one
shared step sequence and the truncation error is common-mode and cancels, giving
the separation to `3e-13` relative even at `ε = 1e-8`.

Full method and results: [`docs/EXPERIMENT.md`](docs/EXPERIMENT.md).

## Stage two — surfaces where the curvature varies

![Curvature-aware path sensitivity on parametric surfaces](figures/surfaces-testbed-v1.png)

A parametric surface `r(u, v)` carries its own metric. From one jet come the
Christoffel symbols and the Gaussian curvature, and the geodesic and its Jacobi
field are advanced as one six-component system, because `j'' + K(γ(s)) j = 0`
needs `K` at the moving point.

**47 declared checks, 0 failed.** With no closed form left, four things stand in
for one:

| verification | result |
|---|---|
| **anchoring** — recover the known answers the general way | `s`, `s`, `sin s`, `sinh s` reproduced to `1.1e-13`, `1.1e-13`, `4.4e-13`, `1.2e-14` |
| **two independent routes** — the Jacobi equation vs. differencing the flow | agree to second order, coefficient `(cn² + κ_n² sn²)/6`; exactly `1/6` on the plate and the sphere, where the whole finite-`ε` answer is known and checked sample by sample |
| **self-convergence** — halve the step against a finer run | order 3.96 – 4.01 on every case with anything to converge |
| **invariants** — unit speed, never re-imposed | drift below `2e-12` everywhere |

Two results worth stating plainly:

- **A rolled sheet has exactly the path sensitivity of the flat sheet** — to
  `1e-13`, from a completely different parameterisation. Bending a sheet onto a
  drum changes nothing, because only intrinsic curvature carries an aiming error.
- **A camera measures chords, not distances in the surface.** That is the second
  term above, and on the pseudosphere it is 2.5 times the intrinsic effect —
  the same order as the first-order model's own failure, so a bench that does
  not account for it will mistake one for the other.

And the decision the whole thing exists to support: of 24 candidate starting
headings from one point on a torus, the most tolerant carries an aiming error
**21× less far** than the least tolerant over the same path length, because it
stays on the positively curved side where neighbouring paths refocus.

Full method and results: [`docs/SURFACES.md`](docs/SURFACES.md).

## Run it

```bash
pip install -e ".[dev]"
python examples/run_experiment.py --out out   # both stages: reports + figures, ~45 s
pytest -q                                     # 167 tests, no network, about a minute
```

`--stage constant-curvature` or `--stage surfaces` runs one of them;
`--update-committed` refreshes the tracked reports and figures. The command
exits non-zero if any declared check fails, so it gates CI by itself. Without
installing, prefix with `PYTHONPATH=src`.

## Scope

Stage one's `claim_scope` is `numerical-verification-against-closed-form-solutions`;
stage two's is `numerical-verification-anchored-to-the-constant-curvature-stage`,
and it names stage one as its dependency. Four boundaries are kept explicit:

- A Jacobi field is a first-order variation, not the exact finite distance
  between trajectories. The size of that gap is measured here, not waved at.
- Finding a geodesic does not establish that an arbitrarily long segment is
  globally shortest. Past the conjugate point on the sphere it demonstrably is
  not, and the experiment measures by how much.
- The envelope is first order. `± ε j(s)` is a tube, not a guarantee; stage one
  measures exactly where it stops being the truth.
- No physical measurement exists in this repository. The bench that would
  establish agreement between prediction and measurement is described in
  `docs/INSTRUMENT.md` and has not been built.
